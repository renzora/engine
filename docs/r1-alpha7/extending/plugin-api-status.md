# Plugin API status

Every part of Bevy's API a plugin author might reach for, and what happens when they do.
This page is the reference; [Standalone Plugins](./standalone-plugins.md) is the guide that
explains why the boundary is shaped this way.

| | Meaning |
|---|---|
| **works** | Usable today, and the source is character-identical to Bevy. |
| **differs** | Usable today, but you write something different or it behaves differently. |
| **missing** | Not available. There is a known mechanism and no blocker — nobody has built it. |
| **never** | Structurally blocked. The note says by what. |

> **Read [Traps](./standalone-plugins.md#traps) before this page.** A **missing** row costs you
> a compile error and five minutes. The handful of things that compile and *then* behave
> differently from Bevy are what actually cost people an afternoon, and they are listed there.

## Systems & scheduling

| Bevy | | In a plugin |
|---|---|---|
| Commands as a system param | **works** |  |
| Query<D, F> as a system param, including two or more Query params in one system | **works** |  |
| Res<T> / ResMut<T> for a resource the plugin declared | **works** |  |
| Res<Time> — time.delta_secs() / time.elapsed_secs() | **works** |  |
| Schedules First, PreUpdate, Update, PostUpdate, Last | **works** |  |
| app.init_resource::<T>() / app.insert_resource(value) | **works** |  |
| System parameter count | **differs** | At most 6 parameters — split the system or fold state into one Resource — `into_system!` is generated for arities 1..=6. Bevy generates 0..=16. |
| A system with no parameters — fn tick() {.. } | **missing** | Take at least one param, e.g. fn tick(time: Res<Time>) — `into_system!` starts at arity 1, so a zero-param callable has no impl. Nothing downstream objects — the host already accepts a descriptor with zero queries and zero resources. |
| A tuple of SystemParams as one parameter | **differs** | At most a 6-tuple — `param_tuples!` covers 1..=6. Bevy covers 0..=16 including the unit tuple. |
| #[derive(SystemParam)] for a custom param | **differs** | Implement the public `unsafe trait SystemParam` by hand (declare + fetch) — No derive exists are the only two proc-macro derives). The trait is public with two methods; `Images`/`Meshes` at /:1689 are worked examples. A hand impl can only surface what SystemCall already carries. |
| Capturing closure as a system — add_systems(Update, move \|q: Query<&mut T>\| {.. }) | **missing** | A plain fn or a non-capturing closure — Refused by a const assert in the ergonomic layer, not by the boundary: `materialize` const-asserts size_of::<T>() == 0 and the builder passes null for `user`. The opaque word already round-trips — SystemDesc.user → SystemCall.user, carried at and written back at :2645. |
| add_systems with a tuple — add_systems(Update, (a, b, c)) | **differs** | One system per call, chained:.add_systems(Update, a).add_systems(Update, b) — `add_systems` takes a single `S: IntoSystem<M>` and IntoSystem is implemented only for callables, never for a tuple of systems. The chained form is what shipped plugins write. |
| chain() | **missing** | Put the systems in different schedules (e.g. First then Update) — `add_systems` accepts no configuration; `flags: 0` is hard-coded. The reserved word exists and is documented as where ordering lands; the host rejects a non-zero flags as Invalid. |
| run_if(condition) | **missing** | An early `return` inside the system body — Same reserved `SystemDesc.flags` slot; nothing in the descriptor can carry a condition today. |
| before(other) /.after(other) | **missing** | Put the two systems in different schedules — Same reserved flags slot, plus SystemDesc has no label field at all, so a plugin has no way to name another system — its own or an engine one — across the boundary. |
| in_set(S) / #[derive(SystemSet)] / app.configure_sets(..) | **missing** | Same reserved flags slot; no SystemSet derive and no `configure_sets` anywhere in the App surface. |
| Relative execution order of two plugin systems in the same schedule | **differs** | Each dispatcher is added with no constraints — `Schedules::entry(bevy_label(desc.schedule)).add_systems(system)` — so Bevy's multi-threaded executor may run them in any order or in parallel. That is by design (each dispatcher declares real access so it can schedule freely,, but Bevy would let you pin it and here you cannot. |
| Schedules PreStartup / Startup / PostStartup | **missing** | Do registration in Plugin::build; for a one-time spawn, guard an Update system with a Resource flag — `Schedule` has five constants and `is_known` is `self.0 < 5`. Plugin::build is not a substitute for spawning: Commands exists only inside a SystemCall. An unknown schedule id is warned and re-homed to Update. |
| FixedFirst / FixedPreUpdate / FixedUpdate / FixedPostUpdate / FixedLast / RunFixedMainLoop | **missing** | Absent from the five-value Schedule list. Appending is a MINOR bump on an append-only newtype, and an unknown value degrades to Update with a warning rather than being dropped. |
| Other built-in Bevy schedules (SpawnScene, StateTransition, Main) | **missing** | Same five-value list; silently re-homed to Update with a warning. |
| A plugin-defined schedule — #[derive(ScheduleLabel)] struct MySchedule | **never** | A schedule crosses as one u32 (`#[repr(transparent)] struct Schedule(pub u32)`, resolved by a closed match on the host. There is no encoding for a label the host has no constant for. |
| Local<T> | **missing** | #[derive(Resource)] + ResMut<T> — No SystemParam impl. The per-system storage slot already exists unused: SystemDesc.user round-trips to SystemCall.user and the host carries it → :2645). |
| ParamSet<(P0, P1,..)> | **missing** | No impl. Declaring the conflicting params separately does not substitute — Bevy's access check fires, the host returns RegisterStatus::AccessConflict and `add!` fails the whole load. |
| Option<Res<T>> — and Bevy's skip-the-system-when-missing behaviour | **differs** | Res<T> then `is_present()` / `get()` — There is no `SystemParam for Option<T>`. Bevy declines to run a system whose Res<T> is missing; here the system runs and a bare deref panics with "resource not present". |
| MessageReader<M> / MessageWriter<M> (Bevy 0.19's rename of EventReader/EventWriter — neither spelling exists here) | **missing** | Nothing in SystemCall carries message buffers. The mechanism is established — `input`, `meshes`, `images`, `http` are all per-call sources appended at the end of the struct — but no message source has been added. |
| app.add_message::<M>() / app.add_event::<E>() | **missing** | No such method anywhere in the App surface, matching the absence of the reader/writer params. |
| Single<D, F> | **missing** | Query<D, F> plus a manual is_empty()/len() check — No impl, and Single's defining behaviour — silently skipping the system unless the match count is exactly one — needs the run-condition machinery the reserved SystemDesc.flags is for. |
| Populated<D, F> | **missing** | Query<D, F> plus `if q.is_empty() { return; }` — Same as Single: no impl, and skip-on-empty needs run conditions. |
| RemovedComponents<T> | **missing** | No impl and no removal buffer crosses; it would arrive as another appended per-call source like `input` or `http` and the append pattern at :876-882). |
| SystemChangeTick | **missing** | No impl and no change tick crosses at all — the per-call context is FrameCtx's two f32s. |
| Deferred<T> (a custom SystemBuffer) | **missing** | No impl. The only deferred buffer here is the Commands sink, for which the host supplies Bevy's own Commands. A plugin-defined buffer needs a second host-called entry point at apply time. |
| NonSend<T> / NonSendMut<T> / NonSendMarker | **never** | NonSend names a host Rust type by TypeId. The boundary can only carry a resource the plugin itself described with a ComponentDesc — `register_resource` is the only resource entry in the Interface and `res_ptr` matches on the id the plugin got back. |
| &World / World / DeferredWorld / &Archetypes / &Entities, and exclusive systems — fn setup(world: &mut World) | **never** | A plugin links no Bevy, so there is no World type to name, and SystemCall.host is documented **always null while a system runs** because the world is borrowed by the queries. The only system entry shape is `unsafe extern "C" fn(*const SystemCall) -> SystemStatus`. |
| ApplyDeferred / apply_deferred as an explicitly scheduled system | **never** | A plugin registers only its own dispatcher, never a host system. Command application is Bevy's, happening after the dispatcher that queued it, and SystemDesc cannot express a barrier. |
| Res<T> / ResMut<T> for an engine-owned resource | **missing** | CONFLICT between audits (impossible vs planned) — planned wins on evidence. The Interface has `component_id_by_name` but no resource equivalent, and it is explicitly append-only, so adding `resource_id_by_name` mirrors an existing call exactly. The real limit is narrower than 'impossible': only a #[repr(C)] plain-data engine resource could ever be mirrored, the same rule host_component! already imposes. |
| Time's other accessors — delta(), elapsed() (Duration), delta_secs_f64(), elapsed_secs_wrapped(), wrap_period() | **missing** | The shim's Time wraps FrameCtx, which carries two f32s and nothing else. FrameCtx is embedded in SystemCall **by value**, so it cannot be widened — extra clock values must be appended at the end of SystemCall instead, which is a MINOR bump nobody has spent. |
| Res<Time<Fixed>> / Time<Real> / Time<Virtual>, time.pause(), set_relative_speed | **missing** | CONFLICT between audits (planned vs impossible), and both are half right: the *values* are appendable exactly like `input` was, but the Bevy *spelling* can never appear — a generic resource has no C representation, the same argument that flattened ButtonInput<T>. Expect a distinct non-generic type, not Time<Fixed>. FixedUpdate is not an available schedule either. |
| Res<State<S>> / ResMut<NextState<S>> / #[derive(States)] / app.init_state | **missing** | Hand-roll: a #[derive(Resource)] struct holding the current state — There is no States trait or derive — Component and Resource are the only derives — and no state machinery on App. |
| OnEnter(S) / OnExit(S) / OnTransition schedules | **never** | Schedule is a plain u32 resolved through a closed match. A label parameterised by a plugin-defined state type has no encoding in that word. |
| Plugin::finish() / cleanup() / name() / is_unique() | **missing** | Put everything in build() — The Plugin trait declares only `build` and the single ABI entry point calls it once and inspects the result. |
| Gizmos (debug drawing) | **missing** | No Gizmos param and no gizmo entry anywhere in the Interface is the complete table). Lines and colours are plain data and the table is append-only, so this is an append, not a design problem. |

## Queries & filters

| Bevy | | In a plugin |
|---|---|---|
| Query<&T> | **works** |  |
| Query<Entity> | **works** |  |
| Query<Option<&T>> | **works** |  |
| With<T> | **works** |  |
| Without<T> | **works** |  |
| q.is_empty() | **works** |  |
| Query<&mut T> | **differs** | Same declaration; the item is a bare `&mut T`. `for mut t in &mut q` warns unused_mut — Item = &'a mut T, not Bevy's Mut<'w, T> (bevy — so no is_changed / set_changed / bypass_change_detection / into_inner. Change detection also differs: the host memcmps your staged bytes against a pre-call baseline and only writes back on a real difference. |
| Query<Option<&mut T>> | **differs** | Item is Option<&mut T>, not Option<Mut<T>> — Same divergence as &mut T, and the same memcmp-gated write-back. |
| Query data tuples — Query<(&A, &B, &C, &D)> | **differs** | Flat tuples up to 3; nest to go wider — Query<(&A, (&B, &C, &D))> — Impls exist only for the 2- and 3-tuple. Bevy covers 0..15 (bevy. Nesting genuinely works because offsets are A::CELLS-based and compose, but a flat 4-tuple does not compile. |
| Query filter tuples — (With<A>, Without<B>, With<C>, With<D>) | **differs** | Up to 3 flat; nest for more. `(With<A>,)` must be written `With<A>` — Impls exist for (), the 2-tuple and the 3-tuple only — there is no 1-tuple impl and no 4+. Bevy covers 0..15 (bevy. |
| Or<(With<A>, With<B>)> | **differs** | 2 to 4 branches, each containing only With, Without or a nested Or — `or_filters!` covers 2, 3 and 4 branches; Bevy covers 0..15. The host's apply_filters honours only With/Without/nested-Or inside a bracket and drops anything else to a `_` arm, so `Or<(Changed<A>, With<B>)>` is not expressible. |
| q.iter() / q.iter_mut() / for x in &q | **differs** | Same spelling; there is no read-only projection, so plan for one live iterator at a time — `iter(&self)` returns D::Item — on a Query<&mut T> that is `&mut T` from a *shared* borrow, and `iter_mut` is literally `self.iter()`. Bevy's iter returns QueryIter<..., D::ReadOnly, F> (bevy. Two simultaneous iterators alias, and rustc will not stop you. |
| Query length — q.count() | **differs** | q.len() — The shim spells it `len()`, a name Bevy's Query does not have; Bevy's spelling is `count()` (bevy. QueryIter is not ExactSizeIterator either, so `q.iter().len()` does not work. |
| q.get(entity) / q.get_mut(entity) / q.contains(entity) / q.iter_many(..) | **missing** | Iterate and compare the Entity term yourself — The whole Query impl is iter / iter_mut / len / is_empty. QueryView already carries the entity column, so these are plugin-side additions with no ABI change. |
| q.single() / q.single_mut() | **missing** | q.iter().next() — Absent from; the row count is already in QueryView. |
| q.par_iter() | **missing** | Chunking the staged cells needs no ABI change — they are one contiguous host-owned buffer for the whole call — but the plugin has no handle on Bevy's ComputeTaskPool, so it would be the plugin's own threads oversubscribing the schedule. |
| q.transmute_lens::<NewD>() | **missing** | QueryData exposes only the compile-time CELLS count with no runtime component→cell map, so narrowing to a new D has nothing to look up until the shim keeps one. |
| Query<Ref<T>> | **missing** | &T, with no access to the change tick — QueryData has no tick channel and none of the 11 Access values carries one. The host already holds the ticks it would need (bevy_ecs, so this is an appended Access value plus a wider cell. |
| Query<Mut<T>> | **missing** | &mut T — No Mut type exists in the shim. Same mechanism as Ref<T> — a wrapper type plus tick plumbing on an appended Access value. |
| Query<Has<T>> | **missing** | Option<&T>, then test for None — A QueryData impl over the existing ReadOptional cell (null ⇒ false,; no ABI change needed. |
| Query<AnyOf<(&A, &B)>> | **missing** | Query<(Option<&A>, Option<&B>), Or<(With<A>, With<B>)>> — Purely a missing QueryData impl — it decomposes into optional cells plus an Or bracket, both of which already exist. |
| Added<T> / Changed<T> / Spawned | **missing** | No Access value for them Access stops at OrEnd = 10), but the host already walks a FilteredEntityRef per row in `gather` and those carry the ticks. Note the semantics would differ once shipped: a plugin's &mut write only bumps a tick when the bytes actually change. |
| Allow<T> — bypass DefaultQueryFilters | **missing** | QueryBuilder has no allow_id, but `extend_access` with FilteredAccess::add_archetypal is exactly what Allow<T> does (bevy. One appended Access value plus a host branch. (There is no `allow_disjoint` in bevy_ecs 0.19.) |
| Query<EntityLocation> | **missing** | Plain-old-data, so it fits the cell model; it needs an appended Access/marshal pair and nothing more. |
| Query<&Name> | **missing** | With<Name> / Without<Name> work today as filters — Name is force-registered so the name resolves, but it holds a String and the default marshal is a verbatim byte copy — declaring a mirror for it would hand the plugin a pointer into the engine heap. Doing it properly needs a Str256-backed marshal case, which is the mechanism Transform already uses. |
| Reading an entity's children — Query<&Children> | **missing** | CONFLICT between audits (impossible vs planned). Both are right about different things: it can never be a query *cell*, because every term has one fixed cell_size and cells are raw byte copies while Children is a Vec<Entity>. But a two-pass count-then-fill read source is an established pattern — Meshes::read does exactly that — so the capability is planned even though the Bevy spelling is not. |
| Query<EntityRef> / EntityMut / FilteredEntityRef | **never** | QueryDesc declares the whole access set at registration and the host's QueryBuilder is driven only by declared terms. A plugin has no Rust type for an arbitrary host component, and up-front access declaration is what lets plugin systems schedule in parallel; whole-entity dynamic access has neither. |

| #[component(name = "CRT")] — inspector label | **differs** | #[component(name = "..")] — A plugin-only key with no Bevy counterpart; only `name` is read out of #[component(..)] (derive, consumed host-side at. | #[require(Transform)] | **never** | The derive accepts only `component` and `field` attributes (derive, so #[require] is an unknown-attribute compile error. | #[relationship] / #[relationship_target] | **never** | The derive rejects the attribute (derive and the host passes `relationship_accessor: None` to new_with_layout. |
| #[derive(Resource)] | **differs** | #[derive(Resource, Default)] #[repr(C)] struct Score {.. } — Registers through the same ComponentDesc path (derive, so it inherits every component restriction — struct only, Default required, closed field-type set, no String/Vec. | Collecting an HTTP response | **differs** | fn collect(http: Http) { if let Some(r) = http.poll(TAG) {.. } } — A bare system param (not Res<..>), polled every frame, delivered exactly once, with a two-pass probe-then-fill copy. The body is String::from_utf8_lossy, so binary responses are mangled. |
| HTTP verbs beyond GET/POST, custom headers, timeouts, status-line access | **never** | HttpOp has exactly two values and HttpHeader carries only tag/url_len/body_len. The engine's own HttpInbox::request has no header parameter either, so there is nothing to widen to. |
| info!("spawned {n} boids") | **differs** | info(&format!("spawned {n} boids")) — A function taking &str, not a tracing macro — no format arguments, no structured fields, no target:, no span context. Every line is prefixed `[plugin]` with no plugin name. |
| debug! / trace! | **differs** | log(LogLevel::Debug, msg) after use renzora_plugin::sys::LogLevel — The levels exist on the wire and the host routes them, but the prelude re-exports only info, warn and error. |
| Logging before Plugin::build is entered | **never** | The interface pointer is stashed in a static at init; before that, log is a silent no-op. |
| Hot reload of plugin code while the editor runs (Bevy has no equivalent) | **differs** | Nothing — edit a.rs or.wgsl under plugins/ and save — Components and resources survive untouched because their ComponentIds are name-keyed; systems, panel BSN, panel title/icon, render passes, post-process effects and shaders are re-registered. Every failure mode leaves the running build in place. A reload leaks one library image and one shadow-copied file by design, because a mapped DLL cannot be replaced on Windows. |
| Adding a NEW panel, render pass or post-process effect during a reload | **never** | Restart the editor — register_panel_content is an &mut App extension that runs only from Plugin::finish, and a system has no &mut App — the log says so once per id. Editing an existing one works. |
| Pre-declared host-component mirrors a plugin can query without setup | **differs** | Transform (full read/write data) plus Mesh3d and Visibility, and behind their features AnimState and PhysicsState — Only five, and two are opaque markers: Mesh3d and Visibility are `pub struct X(())`, documented filter-only. Nothing enforces that — `&Mesh3d` compiles and yields a reference to a zero-sized nothing accepts any T: Component). GlobalTransform and Name are force-registered host-side but have no mirror and cannot get a naive one: Affine3A is SIMD-laid-out and Name holds a String. |
| Exposing your own in-tree component to standalone plugins | **differs** | Make it #[repr(C)] plain data, register_type it, publish its type path; plugin side declares host_component!(Mirror, "my_crate::path::MyComponent") — Matching is by string through the reflection registry, so a rename or moved module is silent on both sides and presents as a query that matches nothing forever. Both existing bridges assert the two agree at startup precisely because nothing else would catch it. |
| Depending on a Bevy ecosystem crate (bevy_hanabi, bevy_mod_outline, avian3d, leafwing-input-manager,..) | **never** | Their public APIs take real Bevy types; the Transform, Query and App here are shims with no relationship to Bevy's. Anything needing them is an in-tree engine crate compiled against real Bevy — the deliberate split between the two plugin tiers. |

215 entries: **22** work identically, **95** differ, **60** are missing, **38** never will be.

The shape of that is the honest summary of the surface. **Most of what is absent is absent
because nobody built it yet, not because it cannot be built** — the *missing* column is a
backlog, not a boundary. The real boundary is the *never* column, and it is almost entirely
one of four things: a Bevy generic that would have to be instantiated, a capturing closure, a
type with a destructor, or a method that is compiled code in the host binary.

The *differs* column is the one to read closely. It is the largest, and every row in it is a
place where Bevy muscle memory produces something that either does not compile or does not
do what you meant.

## Roadmap

The *missing* column above is a backlog, and this is the order it gets worked in. Ordered by
how many rows each step deletes, not by how interesting it is.

**ABI** says what a step costs compatibility: *none* is plugin-side or host-side only and every
built plugin keeps working; *MINOR* appends to the contract and older plugins keep working;
*MAJOR* refuses every plugin built before it.

### Shipped

| | What it changed | ABI |
|---|---|---|
| Interface table repaired | Two functions had been *inserted* mid-struct and recorded as appended, so a plugin built against 2.5–2.10 would have called the slot it compiled for and landed in a different function. No field order makes every historical MINOR correct, so all of them are refused by name. | **MAJOR** → 3.0 |
| Every offset-keyed table pinned | `Interface`, `SystemCall`, `FrameCtx`, `CommandSink`, `MeshSource`, `ImageSource`, `HttpSource` — field names *and* written types, so a signature change at an unchanged offset fails too. `FrameCtx` is included because `SystemCall` embeds it by value, which makes appending one float there an ABI break authored in a different struct. | none |
| `set_material` | A plugin material can be applied to geometry the plugin did not create — an imported model, a shape the user authored. Before this, `make_renderable` set mesh, material and transform together, so a custom shader could only ever land on shapes the plugin spawned itself. | MINOR 2.12 |
| Custom material path made to work | Bind group corrected to `@group(3)`; the plugin supplies a fragment only, so Bevy's mesh vertex stage keeps skinning and morph targets; unused texture slots bind a fallback so the bind group matches its layout; the prepass and shadow passes keep Bevy's own fragment. | none |
| `rotate_x/y/z` corrected | They post-multiplied, so they silently *were* `rotate_local_*`. Copied Bevy source spun the wrong way once an object was tilted, with no diagnostic. `rotate_local_*` added with the old bodies. | none |
| Documented rules made real | Three rules the docs stated and nothing enforced are now compile errors: a component owning a `String`/`Vec`/`Box` is refused by the derive; `Query::iter()` yields a read-only projection so nested iteration cannot alias; and the four structs handed to plugins as a first-field pointer assert that the field is at offset zero. | none |
| Host-mirror data gate | Reading an engine component as *data* now requires the owning crate to expose it. Filtering is unrestricted. Without the gate a plugin could name any reflected component and be handed its raw bytes — including `Window`, which owns a `String`, and `GlobalTransform`, whose layout changes with the engine's SIMD backend. | none |
| Textures, geometry read/write, strings, HTTP, physics | See the version history in [Standalone Plugins](./standalone-plugins.md#versioning). | MINOR 2.5–2.11 |

### Next — makes the documented rules true

Each of these turns a [trap](./standalone-plugins.md#traps) into something that cannot happen,
which is worth more than any new feature on this page.

| | What it unlocks | Size | ABI |
|---|---|---|---|
| Interface prefix hash | Closes the failure class the 3.0 repair was for, at load time rather than build time: a per-field cumulative hash over `(name, written type)`, append-stable, checked in the handshake. Catches both insertion and a signature change at an unchanged slot. | ~100 lines | MINOR |
| Payload descriptor re-mint rule | `MeshDataDesc`, `ImageDesc`, `ComponentDesc` and the domain payloads are read through pointers, so reordering their fields is invisible to the table tests and equally fatal. The rule — never edit one, mint a new one beside it — costs nothing and would have prevented both incidents. | doc only | none |

### Then — deletes whole classes of workaround

| | What it unlocks | Size | ABI |
|---|---|---|---|
| `RemovedComponents` by `ComponentId` | Deletes the per-frame liveness sweep in every plugin that owns anything. Both shipped plugins hand-roll one. The param has empty access declarations, so it can never conflict. | medium | MINOR |
| `Added<T>` / `Changed<T>` | Deletes the hand-rolled signature hashing in `hair` and `text3d`, and `ripple`'s `_ready` flag. `QueryBuilder` cannot express these, so it routes through change ticks and row skipping — row-level rather than archetype-level, so it loses Bevy's whole-table skip. | medium | MINOR |
| Reflective field patch | The complement to BSN insert, which replaces rather than patches. The only way to nudge one field of a live `Camera` or `PointLight` without resetting the rest. Must refuse immutable and relationship components. | ~80 lines | MINOR |
| Capturing closures as systems | Recovers `Commands::queue`, `add_observer`, `entity.observe`, and `on(\|ev\| …)` in BSN. The per-system token already round-trips through the ABI unused — the refusal is a `const` assert in the ergonomic layer, not a boundary constraint. | medium | none |
| Syntax-parity sweep | Tuple arities to Bevy's 15/16, `add_systems(Update, (a, b))`, `info!`/`warn!` as macros, `Query::single`/`get`/`contains`, `Option<Res<T>>`, `Local<T>`, and the missing maths (`Vec2`/`Vec4`/`Color`/`Dir3`, `Quat::from_euler`, `looking_at`). This is where "zero syntax changes" is won or lost in an author's first hour, and none of it touches the ABI. | medium | none |
| Deferred asset creation | Deletes the fixed-pool idiom — `hair` reserves 16 meshes, `text3d` 64, each with a slot index stored on the component to survive reload. The pattern already exists for entities. | medium | MINOR |
| Run conditions, ordering, system sets | `SystemDesc.flags` is reserved and enforced-zero for exactly this. Ordering *between plugin systems* is tractable; ordering against *host* sets needs a curated published map, because the set interner is private. | large | MINOR |
| Schedules by name | `Startup`, `FixedUpdate` and the rest. Note `Startup` is a trap under hot reload — a reloaded plugin's `Startup` system would never fire, since reload happens mid-frame. | small | MINOR |
| Per-entity plugin materials | Today the settings component is read from the first entity carrying it *anywhere in the world* and broadcast, so two entities using one plugin material always look the same. | one file | none |
| Reflective mirroring | Read *any* registered host component by type path with no hand-written `#[repr(C)]` mirror. Kills the mirror-layout hazard permanently instead of guarding it. Placed last deliberately: the largest contained piece of work here, and the steps above deliver most of the practical value first. | large | MINOR |

### Not planned

The 38 *never* rows, and two things that look like natural next steps and are not:

- **Reflected function calls** — "call any engine function by name". Three independent
  blockers: the feature is not compiled, the registry is created empty with no call sites
  anywhere in Bevy, and `World` does not implement `Reflect` so no function taking it could be
  registered even if it were.
- **Direct pointers into component storage.** Would save the per-entity copy, but loses the
  comparison against a baseline that stops every plugin system marking everything it merely
  read as changed. The real cost is the per-cell allocation, which is fixable without this.
